# Plary

Plary is a personal library for Figma designs. It lets designers save screens, frames, and prototype starting points from Figma, then find them later in a searchable web app.

The prototype is intentionally small: a Figma plugin for capture, a Next.js web app for browsing, and Supabase for auth, data, and thumbnail storage. The product question is whether designers actually save and revisit designs when the capture flow is easy.

Plary is open source under the [MIT license](LICENSE). To run it for yourself or your organization, see **[SELF_HOSTING.md](SELF_HOSTING.md)** — it covers the database, the web app, your own Figma OAuth app, and building the plugin against your deployment.

> **Security model:** this app ships **no Row Level Security policies**. All access control is application-layer — server routes use the Supabase service-role key, which bypasses database security entirely. That is a deliberate prototype trade-off: it is acceptable for a single-org self-hosted deployment where you control the server, but it means the service-role key must never leak and any route bug has no database-level backstop. Contributing an RLS policy set is a welcome improvement.

## Product

Plary works like "Pocket for Figma designs."

Designers can:

- Save the currently selected Figma frame or prototype from a Figma plugin.
- Capture title, description, Figma URL, selected node metadata, design kind, and a thumbnail.
- Organize saved designs into one or more collections.
- Browse all saved designs in a web library.
- Search saved designs by title or description.
- Open a saved design detail page with an embedded Figma view.
- Manage collections and plugin setup from the web app.

The prototype does not include teams, organizations, roles, sharing, approvals, analytics, SSO, or custom prototype playback.

## Main User Flow

1. Sign in to the Plary web app with a Supabase magic link.
2. Open Settings and connect a Figma account (OAuth) — required before saving.
3. Import the Plary development plugin into Figma.
4. Click "Login with Plary" in the plugin — a browser opens to authorize and the plugin receives a token automatically. (Pasting a token from Settings remains available as a fallback.)
5. Select a Figma frame or prototype starting point.
6. Save it to Plary with a title, optional description, kind, and collections.
7. Return to the web app to search, browse, and reopen saved designs.

## Features

### Figma Plugin

The plugin runs inside Figma and saves the current selection to Plary.

It captures:

- Selected node id, name, and type
- Current page name
- Figma file key
- Auto-detected Figma URL
- Whether the selection is a `prototype` or `screen`
- PNG thumbnail exported at 2x
- User-entered title, description, and collections

The plugin watches Figma selection changes while it is open, so the form updates when the user selects a different frame. Saved designs are created immediately; thumbnail upload happens afterward in the background.

The plugin's API base URL is configured at build time via the `PLARY_API_BASE` environment variable (defaults to `http://localhost:3000`). For production, build with `PLARY_API_BASE=https://your-domain.vercel.app npm run build`.

### Web App

The web app provides:

- Magic-link login
- Library grid of saved designs
- Search and kind filtering
- Cursor-based pagination
- Prototype/design detail pages
- Figma embed rendering
- Collection list and collection detail pages
- Collection create, rename, delete, and design membership management
- Settings page with profile, sign out, and plugin token generation

### Supabase

Supabase stores:

- Users through Supabase Auth
- Saved designs in `prototypes`
- Collections in `collections`
- Many-to-many memberships in `prototype_collections`
- Thumbnail images in the `thumbnails` storage bucket

The API uses the Supabase service role key on the server and scopes all data access by the authenticated user. This prototype does not rely on Row Level Security for app authorization.

## Environment Variables

Copy the example file and fill in the values:

```bash
cd web
cp .env.local.example .env.local
```

Required variables:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon/public API key for browser clients |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key for server API routes |
| `PLARY_TOKEN_SECRET` | Secret used to sign plugin JWTs |
| `NEXT_PUBLIC_FIGMA_CLIENT_ID` | Figma OAuth app client id used for embeds |
| `FIGMA_CLIENT_ID` | Figma OAuth client id (server-side, same value as public) |
| `FIGMA_CLIENT_SECRET` | Figma OAuth client secret (server-side only) |
| `FIGMA_ENCRYPTION_KEY` | 32-byte hex key for encrypting Figma tokens at rest |

Optional variables:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | Contact address shown on the privacy page (section hidden when unset) |
| `NEXT_PUBLIC_AUTH_PROVIDERS` | Comma-separated Supabase OAuth providers to offer at login, e.g. `google,azure` (must also be enabled in the Supabase dashboard) |

Generate secrets with:

```bash
openssl rand -base64 32  # for PLARY_TOKEN_SECRET
openssl rand -hex 32     # for FIGMA_ENCRYPTION_KEY
```

Do not expose `SUPABASE_SERVICE_ROLE_KEY` or `PLARY_TOKEN_SECRET` to the browser or commit real `.env.local` values.

## Supabase Setup

1. Create a Supabase project.
2. Open the Supabase SQL Editor.
3. Run `supabase/setup.sql` — a single idempotent script that creates all tables, functions, and the public `thumbnails` storage bucket. (Existing databases keep applying `supabase/migrations/` in order instead; do not run `setup.sql` on them.)
4. Enable Auth email magic links.
5. For local development, add `http://localhost:3000/auth/callback` to Auth redirect URLs.
6. For production, add the deployed `/auth/callback` URL as well.

The current schema has seven tables:

- `prototypes`: saved designs and Figma metadata
- `collections`: user-owned collection records
- `prototype_collections`: many-to-many design-to-collection links
- `figma_connections`: encrypted Figma OAuth tokens and connection health
- `oauth_states`: CSRF protection for the Figma OAuth flow
- `plugin_auth_sessions`: one-time sessions for the plugin's browser-initiated login flow
- `user_sessions`: application-level web session tracking (opaque token in an httpOnly cookie)

## Plugin Development

Install dependencies and build the plugin:

```bash
cd plugin
npm install
npm run build
```

For watch mode:

```bash
npm run watch
```

Import it into Figma:

1. Open Figma.
2. Go to **Plugins -> Development -> Import plugin from manifest**.
3. Select `plugin/manifest.json`.
4. Run **Plugins -> Development -> Plary**.
5. Click "Login with Plary" — a browser opens to authorize and the plugin receives a token automatically. (Pasting a token from the web app Settings page remains available as a fallback.)

The plugin runs in private-plugin mode only: `manifest.json` sets `"enablePrivatePluginApi": true` and the plugin reads `figma.fileKey` directly. It is imported in development mode or published org-privately, never to Figma Community (see [SELF_HOSTING.md](SELF_HOSTING.md) and DECISIONS.md).

## API

All API routes live under `web/app/api`.

### Designs

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/prototypes` | List saved designs for the current user |
| `POST` | `/api/prototypes` | Create a saved design |
| `GET` | `/api/prototypes/:id` | Fetch one saved design |
| `PATCH` | `/api/prototypes/:id` | Update metadata, thumbnail, kind, or collection memberships |
| `DELETE` | `/api/prototypes/:id` | Delete a saved design |

`GET /api/prototypes` supports:

- `q`: search title and description
- `kind`: `prototype` or `screen`
- `archived`: include archived designs when `true`
- `limit`: page size, max 50
- `cursor`: `created_at` cursor for pagination

When another page exists, the response includes `X-Next-Cursor`.

### Collections

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/collections` | List collections with counts and preview thumbnails |
| `POST` | `/api/collections` | Create a collection |
| `PATCH` | `/api/collections/:id` | Rename a collection |
| `DELETE` | `/api/collections/:id` | Delete a collection |
| `GET` | `/api/collections/:id/designs` | List designs in a collection |

`GET /api/collections/:id/designs` supports the same pagination and filtering parameters as `/api/prototypes`.

### Plugin And Uploads

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/token` | Generate a signed plugin token for the logged-in user |
| `POST` | `/api/uploads/thumbnail-url` | Create a signed Supabase Storage upload URL |

The plugin sends the token as:

```txt
Authorization: Bearer <token>
```

### Plugin Auth (browser-initiated login)

| Method | Route | Description |
| --- | --- | --- |
| `POST` | `/api/plugin/auth/init` | Create a pending auth session (unauthenticated), return `session_id` |
| `POST` | `/api/plugin/auth/authorize` | Mark the session ready for the browser-authenticated user (session cookie) |
| `GET` | `/api/plugin/auth/poll` | Plugin polls with `?session=`; returns `pending` / `ready` + JWT / `expired` |

### Figma OAuth

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/figma/oauth/start` | Create a CSRF state and redirect to Figma's OAuth consent page |
| `GET` | `/api/figma/oauth/callback` | Validate state, exchange the code, store the encrypted connection |
| `GET` | `/api/figma/oauth/status` | Return connection health and connected Figma identity |
| `POST` | `/api/figma/oauth/disconnect` | Remove the user's Figma connection |

### Web Sessions

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/auth/callback` | Supabase magic-link callback; exchanges the code and creates an application session |
| `POST` | `/api/auth/logout` | Revoke the application session, sign out from Supabase, clear cookies |
| `POST` | `/api/auth/session/notify` | Mark the current session as notified for new-login detection |

## Auth Model

The web app uses Supabase magic-link sessions, plus an application-level session record (`user_sessions` table, opaque token in an httpOnly `plary_session` cookie).

The Figma plugin uses a long-lived JWT with the Supabase user id as subject and a 365-day expiry. The primary way to get it is the one-click "Login with Plary" flow: the plugin opens the browser to `/plugin/auth`, the browser authorizes the session, and the plugin polls `/api/plugin/auth/poll` until it receives the JWT. As a fallback, users can generate a token from Settings (`/api/token`) and paste it into the plugin.

## Data Model

```sql
prototypes
  id uuid primary key
  user_id uuid references auth.users
  title text
  description text
  figma_url text
  figma_file_key text
  figma_node_id text
  saved_by_figma_user_id text
  thumbnail_url text
  archived boolean
  kind text check ('prototype', 'screen')
  last_viewed_at timestamptz
  created_at timestamptz
  updated_at timestamptz

collections
  id uuid primary key
  user_id uuid references auth.users
  name text
  description text
  created_at timestamptz

prototype_collections
  user_id uuid references auth.users
  prototype_id uuid references prototypes
  collection_id uuid references collections
  created_at timestamptz

figma_connections
  user_id uuid primary key references auth.users
  figma_user_id text
  figma_email text
  figma_display_name text
  figma_avatar_url text
  access_token_encrypted text
  refresh_token_encrypted text
  scopes text[]
  expires_at timestamptz
  health text check ('connected', 'needs_reconnect')
  created_at timestamptz
  updated_at timestamptz

oauth_states
  id uuid primary key
  user_id uuid references auth.users
  state text unique
  created_at timestamptz

plugin_auth_sessions
  id uuid primary key
  session_id text unique
  user_id uuid references auth.users
  status text check ('pending', 'ready', 'expired')
  created_at timestamptz
  expires_at timestamptz

user_sessions
  id uuid primary key
  user_id uuid references auth.users
  session_token text unique
  user_agent text
  ip_address text
  last_seen_at timestamptz
  created_at timestamptz
  expires_at timestamptz
  revoked_at timestamptz
  notified_new_login boolean
```

Collection names are unique per user case-insensitively. Figma OAuth tokens are encrypted at rest with AES-256-GCM.

## Deployment Notes

For a deployed environment:

1. Deploy `web/` to Vercel with root directory set to `web/`.
2. Add all required environment variables in the Vercel dashboard (see Environment Variables table above).
3. Run Supabase migrations (`supabase/migrations/*.sql`) against the production Supabase project.
4. Add the deployed `/auth/callback` URL in Supabase Auth redirect settings.
5. Add the deployed `/api/figma/oauth/callback` URL in the Figma OAuth app redirect settings (if OAuth is configured).
6. Ensure the `thumbnails` storage bucket exists and is publicly readable.
7. Build the plugin for production: `cd plugin && PLARY_API_BASE=https://<deployed-url> npm run build`.
8. Verify `plugin/manifest.json` `allowedDomains` matches the production domain and Supabase project.
9. Import or publish the plugin in Figma.

### Production smoke test

1. Open the deployed Plary app and sign in with a magic link.
2. Copy the plugin token from Settings.
3. Open the plugin in Figma and paste the token.
4. Select a frame and save it.
5. Verify the design appears in the library with a thumbnail.

## Known Limitations

- The plugin is a private plugin (development import or org-private publish), not a Figma Community plugin — Community plugins cannot read `figma.fileKey`.
- The plugin saves one selected node at a time.
- Thumbnail upload is best-effort and can lag behind the initial save.
- Figma embeds require the underlying Figma file to be viewable by the user.
- Figma OAuth is required for saving (data-integrity gate); the plugin token alone is not sufficient.
- No organization/team support.
- No sharing, permissions, or collaboration features.
- No production-grade RLS policy set is included.
